# 0.1.3 — 2026-10-17

## Added

- **`zenodo_get_record` continuations** (#17) — `record` carries `additional_description_count`, `keyword_count`, `funding_count`, and `community_count`, and each additional description carries `length` and `truncated`. Every cut except the file list is listed in top-level `continuations[]` (`field`, `index?`, `unit`, `shown`, `total`, `cursor`). The new `cursor` input, passed with the same `id`, returns a `window` of that field in place of `record` (8,000 characters of text, or the next page of entries). A bad, foreign, or stale cursor fails as `invalid_cursor`.
- **`zenodo_lookup_vocabulary` `reachable`** (#15) — the entries reachable through the 10,000-entry window, beside `total`; above 10,000 the window notice appears on both surfaces.

## Changed

- **Over-cap budgets are served at the cap** (#16) — `size` on `zenodo_search_records`, `zenodo_list_versions`, and `zenodo_lookup_vocabulary` (25), `limit` on `zenodo_list_files` (200), and `max_bytes` on `zenodo_read_file` (65,536) no longer fail `invalid_arguments` above the cap. The applied value drives the request, paging, and output `size` / `limit` / `cap`, and the notice names both values. `size` and `limit` still reject above 10,000.
- **Result window** (#15) — `result_window_exceeded` fires only when `(page − 1) × size ≥ 10,000`, so the page straddling match 10,000 is served short; its message names the last page. `has_more` is `page × size < min(total, 10,000)` on search, versions, and vocabulary. A request past the window with an over-cap `size` now answers `result_window_exceeded` instead of `invalid_arguments`.
- **Size error text** — the response-body cap error prints `33,554,432` with separators.
- **Repo files** — `framework-skills/` synced to mcp-ts-core 0.13.15; the Docker base images and `packageManager` move to Bun 1.4.3.

## Fixed

- **`zenodo_search_records` filtered queries** (#12) — with a filter other than `community` / `all_versions`, a query Zenodo cannot parse fails as `query_syntax` naming the offending token, before any request; it used to return results with the filters silently dropped. Rejected forms: doubled or dangling operators (`climate AND AND model`, `climate AND OR model`, `(climate AND) model`), an unclosed `(` or `[2020 TO`, `metadata.title:` with no value, `climate::model`, `climate~~`, a single-quoted term, a bare `>`, and a stray `]`. Without such a filter the query runs as plain text and `notice` says so.
- **Query parts Zenodo cannot run** (#20) — a boost, fuzziness, or proximity value that is not a number (`climate^1.2.3`, `"x y"~0.5`) and a `"` opened mid-word that never closes (`climate a"b`) fail as `query_syntax` before any request, replacing HTTP 500 `query_failed`. A `"` inside a regex character class (`/[a"]/ b`) no longer trips the unpaired-slash check.
- **HTML entities** (#13) — `htmlToText()` decodes the full HTML 4 named set (252 names plus `apos`) from a table in the module; every named reference in a description now converts and none fails the call.
- **HTML tables** (#13) — each row renders on one line with cells joined by ` | `, whitespace inside a cell collapsed.
- **`<br>` line breaks** (#19) — a newline directly after `<br>` is part of the break instead of doubling it.
- **Not-on-Zenodo guidance** (#18) — `zenodo_get_record` and `zenodo_list_versions` no longer claim an unknown DOI resolves elsewhere; they point to `https://doi.org/{doi}` to check.
- **Own-key lookups** (#21) — a file extension or `files.order` name that matches an `Object` property no longer resolves to the inherited value: `zenodo_read_file` opens a bare code fence, and the name is not kept as a file entry.
