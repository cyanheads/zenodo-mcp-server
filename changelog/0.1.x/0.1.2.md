# 0.1.2 — 2026-10-09

The advertised `tools/list` (every tool's inputSchema, outputSchema, and annotations) is byte-identical to 0.1.1.

## Added

- **Hosted endpoint** — the README documents the public instance at `https://zenodo.caseyjhand.com/mcp`, and `server.json` lists it under `remotes` as a `streamable-http` endpoint.

## Changed

- **Argument repair** — an integer sent for a string argument is repaired before validation (`id: 7912833` → `"7912833"`) (mcp-ts-core 0.13.9). A numeric string sent for a number argument (`size: "5"`) and `null` sent for an optional argument (it falls back to the default) are repaired before validation (mcp-ts-core 0.13.14).
- **Error results** — tool error results end with `request <id>` and carry `data.requestId` (mcp-ts-core 0.13.10). Tools and `ZenodoHttp` no longer forward `ctx.recoveryFor`; the framework fills each declared reason's recovery hint.
- **Session mode** — `createApp()` now declares `sessionMode: 'stateless'`, so HTTP runs stateless with `MCP_SESSION_MODE` unset (unset used to resolve to stateful); an explicit `MCP_SESSION_MODE` still overrides it.
- **`zenodo_search_records`** — an unknown `resource_type` rejection now puts the pointer to `zenodo_lookup_vocabulary` before the list of valid ids, so it survives the framework's 1,024-character cut on rejection lines (mcp-ts-core 0.13.14).
- **`server.json`** — the npm entries drop the `run`/`start:*` arguments and set `runtimeHint: "npx"`, and the `streamable-http` entry fixes `MCP_TRANSPORT_TYPE` to `http`, so a registry client starting the HTTP entry gets the HTTP transport (mcp-ts-core 0.13.11 template).
- **Docker** — dependencies install in a `deps` stage on the build platform, cross-installed per architecture (mcp-ts-core 0.13.10); musl-only packages are pruned (0.13.11); the base images move to Bun 1.4.2 (0.13.7). The image no longer sets `MCP_FORCE_CONSOLE_LOGGING`.
- **Repo files** — `.gitignore` ignores every `.env*` file except `.env.example`, `.env.template`, and `.env.sample`, `.dockerignore` excludes `.env*` and the MCP Registry token files, `package.json` `files` carries `!dist/*.mcpb`, `.mcpbignore` excludes `docs/idea.md`, `logs/`, `.cache/`, `coverage/`, and `tests/`, and the CodeQL workflow runs one job per language. `.env.example` lists the new framework variables.

## Fixed

- **Look-alike hosts in `id`** — `host.endsWith('zenodo.org')` → `host.endsWith('.zenodo.org')` in `src/services/zenodo/identifiers.ts`: hosts such as `evilzenodo.org` were told they were "a different Zenodo instance" and now get the "is not zenodo.org or doi.org" message. `sandbox.zenodo.org` keeps the Zenodo-instance message. Only the message changes, not what is accepted.
